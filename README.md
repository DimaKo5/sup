# CollegeSupport

CollegeSupport ведёт учёт обращений технической поддержки колледжа. Учебная практика УП.02, вариант 6.

| Проект | Назначение |
|---|---|
| Core | Предметная область, правила переходов, статистика, импорт и экспорт |
| Data | SQLite, EF Core, миграции и вымышленные демонстрационные данные |
| Api | REST API, JWT, проверка ролей и журнал |
| Desktop | Рабочее место WPF |
| Tests | Модульные и интеграционные тесты xUnit |
| UiTests | Сценарии интерфейса на FlaUI |

## Запуск в Visual Studio

1. Откройте `CollegeSupport.slnx` в Visual Studio 2026 с нагрузками «Разработка классических приложений .NET» и «Разработка ASP.NET и веб-приложений». Требуется SDK .NET 10.
2. В списке рядом с зелёной стрелкой выберите **CollegeSupport (Api + Desktop)**. Visual Studio запомнит выбор для этой рабочей копии.
3. Нажмите **F5**. Локальный API доступен по адресу `http://localhost:5006`. При первом запуске создаётся SQLite с демонстрационными данными и генерируется ключ подписи JWT.

Учебные учётные записи создаёт `CollegeSupport.Data/DbInitializer.cs`. Доступны `admin`, `dispatcher`, `technician1` и `technician2`. Техник видит и меняет только назначенные ему обращения. Кнопка **Выйти** возвращает к форме входа.

Вкладка **Обращения** обновляет список при вводе части ФИО, кабинета, телефона или названия оборудования и при выборе статуса. Поиск по кириллице учитывает совпадения в разном регистре. Если изменение статуса вывело бы выбранное обращение из текущего фильтра, окно переключает фильтр на новый статус. Вкладка **Сотрудники и кабинеты** показывает справочник администратору и диспетчеру. Вкладка **Пользователи** доступна администратору для просмотра и создания учётных записей.

## Сборка и автономный запуск

Команда `./build.ps1` собирает Release и запускает модульные и интеграционные тесты. Команда `./tools/publish.ps1` собирает ZIP Windows x64 с сервером и клиентом. После распаковки запустите `Start-CollegeSupport.ps1` из PowerShell. SQLite автономного выпуска находится в `%LOCALAPPDATA%/CollegeSupport/portable`.

Журналы находятся в `logs` в рабочей папке API и в `%LOCALAPPDATA%/CollegeSupport/logs` для клиента.

## Ветвление

В `main` хранится проверенный выпуск, в `develop` — интеграция работ. Ветки `feature/<номер>-<имя>` создаются от `develop`. В PR указывают связанную задачу и проверки. Упрощённый Git Flow оставляет отдельную ветку для учебной интеграции до выпуска.
