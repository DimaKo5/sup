# Работа 26. Оптимизация производительности

Замер выполнен в Release на локальном Windows x64 и .NET 10. Для SQLite использована отдельная база с 10 000 обращений и связями с сотрудниками. Для каждого варианта сделан прогрев, затем взята медиана семи запусков. Проверка нормализованных телефонов использует 1000 успешных поисков по коллекции из 10 000 ключей, коллекции подготовлены до замера.

| Операция | До, мс | После, мс | Изменение |
|---|---:|---:|---|
| Чтение 10 000 обращений с сотрудниками и техниками | 513,102 | 370,763 | Запрос списка работает без отслеживания EF Core |
| 1000 проверок дубликата по 10 000 телефонам | 55,453 | 0,153 | Поиск в HashSet вместо линейного прохода по List |

Промежуточный вариант с `AsNoTrackingWithIdentityResolution` был медленнее запроса с отслеживанием на этом наборе данных: 484,538 мс против 396,498 мс в том же прогоне. Запрос по одному ID сохраняет отслеживание для изменений.

Повторный запуск: `dotnet run --project tools/CollegeSupport.Benchmarks -c Release`. Замеры чтения относятся к репозиторию SQLite. Сетевой HTTP и отрисовка таблицы в них не входят.
